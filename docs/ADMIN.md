# Админ-панель (`@joymusic/admin`)

SPA для владельцев и администраторов заведений: заведения, QR-коды, диджеи, сессии, модерация, аналитика, брендинг. Vite 8, React 19, TanStack Router и Query, Tailwind 4, дизайн-система `@joymusic/ui`. Панель всегда тёмная (тема Club). Темы заведений видны только в превью на страницах «Заведения» и «Брендинг».

Языки: русский (по умолчанию), узбекский (латиница), английский. Выбор хранится в `localStorage` и переключается в шапке, в палитре команд и в настройках.

## Запуск

```sh
node apps/api/scripts/test-services.mjs start
cp apps/api/.env.example apps/api/.env
pnpm --filter @joymusic/api db:migrate
pnpm --filter @joymusic/api db:seed
pnpm --filter @joymusic/api dev
pnpm --filter @joymusic/admin dev
```

Панель открывается на `http://localhost:5173`. Вход демо-владельца: `demo@joymusic.uz` и пароль из `docs/API.md`. Аккаунт `dj@joymusic.uz` нужен для проверки ограничений по роли.

Адрес панели должен входить в `CORS_ORIGINS` API (в `.env.example` уже есть `http://localhost:5173`).

| Переменная              | По умолчанию            | Назначение                                                        |
| ----------------------- | ----------------------- | ----------------------------------------------------------------- |
| `VITE_API_URL`          | `http://localhost:4000` | адрес API                                                         |
| `VITE_GOOGLE_CLIENT_ID` | пусто                   | если задан, на входе появляется кнопка Google (Identity Services) |
| `VITE_PUBLIC_WEB_URL`   | `http://localhost:3000` | база гостевой ссылки `/v/<slug>` на странице заведения            |

Шаблон лежит в `apps/admin/.env.example`, секретов в нём нет.

Скрипты пакета: `dev` (порт 5173), `build`, `preview` (порт 5173), `lint`, `typecheck`, `test`, `e2e`, `screenshots`.

## Структура

```
apps/admin
  src/
    main.tsx, router.tsx        точка входа и маршруты (код, без генерации)
    providers.tsx               i18n, Query, подсказки, тосты, сброс кэша при смене сессии
    lib/                        сессия, клиент API, ошибки, права, форматы, данные графиков, формы, QR
    queries/index.ts            запросы и мутации с оптимистичными обновлениями
    i18n/messages/*.ts          тексты: одна запись на ключ сразу с uz, ru, en
    shell/                      каркас: сайдбар, шапка, хлебные крошки, палитра команд, горячие клавиши
    charts/                     графики на чистом SVG: столбцы, линии, горизонтальные полосы, шкала
    components/                 меню, диалоги, состояния загрузки и ошибок, превью темы, панель сохранения
    pages/                      auth, overview, venues, qr, team, sessions, moderation, analytics, ...
  tests/                        vitest и Testing Library
  e2e/                          Playwright против настоящего API
  scripts/                      screenshots.mjs, seed-activity.mjs
```

Контракт с сервером живёт в `@joymusic/shared`: клиент создаётся через `createApiClient`, руками `fetch` нигде не вызывается. Ответы валидируются схемами `routes`.

## Авторизация и сессии

- `access` токен хранится только в памяти вкладки. `refresh` токен лежит в `localStorage` (`joymusic.admin.refresh`). Это осознанный компромисс: у API нет cookie-режима, а без хранения refresh пользователю пришлось бы входить после каждой перезагрузки. Сторонний скрипт в панели один и подгружается только при заданном `VITE_GOOGLE_CLIENT_ID` (Google Identity Services), остальное собирается локально, шрифты встроены. Для продакшена стоит добавить Content-Security-Policy на уровне хостинга.
- Обновление идёт одним запросом (single-flight): все параллельные запросы ждут один и тот же `authRefresh`. Между вкладками обновление сериализуется через Web Locks (`navigator.locks`), поэтому ротация refresh не приводит к повторному использованию старого токена и отзыву семейства.
- Клиент обновляет access за 20 секунд до истечения. Если сервер всё же ответил `401`, запрос один раз повторяется с новым токеном. Если refresh отклонён (`400`, `401`, `403`), сессия сбрасывается и пользователь уходит на `/login?redirect=...`. Сетевая ошибка сессию не сбрасывает.
- Выход из другой вкладки замечается по событию `storage`.
- Заголовок `X-Organization-Id` добавляется к запросам `/v1/admin/*`. Переключатель организации в сайдбаре показан, если у пользователя больше одной. Смена организации очищает кэш запросов.
- `/desktop/authorize?state=&challenge=`: залогиненный пользователь подтверждает «Authorize Joy Music Desktop», панель вызывает `authDesktopAuthorize` и переходит на `joymusic://auth?code=&state=`. Незалогиненный сначала входит и возвращается на ту же страницу. Проверяются длины параметров (`state` 8-128, `challenge` 43-128).
- `/invite/:token`: принятие приглашения (имя и пароль), затем вход.
- Кнопка Google показывается только при `VITE_GOOGLE_CLIENT_ID`.

## Роли

Панель открывается для `owner` и `admin`. Диджей видит страницу «работайте в десктоп-приложении» (`/dj`) и не попадает в разделы панели. Экран подтверждения десктопа доступен любой роли.

| Возможность                              | owner | admin | dj  |
| ---------------------------------------- | :---: | :---: | :-: |
| Открыть админ-панель                     |  да   |  да   | нет |
| Заведения: создание, настройки, удаление |  да   |  да   | нет |
| QR-коды и печатные макеты                |  да   |  да   | нет |
| Приглашать, менять роли, убирать людей   |  да   |  да   | нет |
| Управлять владельцами                    |  да   |  нет  | нет |
| Модерация, бан устройств                 |  да   |  да   | нет |
| Аналитика и журнал аудита                |  да   |  да   | нет |
| Подтвердить вход десктопа                |  да   |  да   | да  |

Правила для людей дублируют сервер, чтобы интерфейс объяснял отказ заранее: последнего владельца нельзя понизить или убрать (подсказка и отключённые элементы, ответ `409` тоже переводится), администратор не трогает владельцев и не выдаёт владельца, себя удалить нельзя. Матрица описана в `src/lib/permissions.ts` и покрыта тестами.

## Разделы

- **Обзор.** Четыре метрики с дельтой к предыдущему периоду такой же длины, часы пик, самые заказываемые, заказы по дням, эфир, быстрые действия, таблица заведений со спарклайнами.
- **Заведения.** Список с поиском и сортировкой, мастер из трёх шагов (адрес проверяется по публичному маршруту `venuePublic`: `404` значит свободно, конфликт `409` при создании тоже обрабатывается с предложением другого адреса), карточка с настройками, живым превью темы и удалением с вводом адреса.
- **QR Studio.** Коды столов (создание одного или пачки, переименование, отключение, удаление, счётчик сканов), превью Joy Code из `@joymusic/qr` в теме заведения, макеты `table-tent`, `sticker`, `poster`, `tv-overlay`, язык, заголовок, вылет и метки реза. Экспорт SVG, PNG (300 dpi), PDF и общий PDF «все столы» через `@joymusic/qr/browser`. Ссылка в коде берётся из `qr.url` ответа API. Язык печати по умолчанию равен языку гостей заведения. Чанк страницы с QR тяжёлый (шрифты в base64), поэтому загружается лениво.
- **Диджеи.** Участники и приглашения, приглашение по email со ссылкой `${origin}/invite/<token>`, смена роли, удаление. Токен показывается один раз при создании. Для ожидающего приглашения кнопка «Новая ссылка» создаёт приглашение заново.
- **Сессии.** История по заведению: диджей, начало, длительность, заказы, сыграно, доля сыгранных.
- **Модерация.** Свои запрещённые слова (добавление и удаление с откатом при ошибке) и бан устройства гостя с подтверждением. Разбана в API нет.
- **Аналитика.** Заведение или вся организация, периоды 7, 30, 90 дней или свои даты. Заказы по дням, по часам (в часовом поясе заведения), самые заказываемые, по столам, доля отклонённых. У каждого графика есть табличный вид.
- **Брендинг.** Название, город, ссылки на логотип и обложку, три темы с превью.
- **Биллинг.** Честная заглушка: платежи не включены, тарифы статичны, цен нет.
- **Журнал аудита.** Человекочитаемые события с фильтрами по типу, человеку и тексту.
- **Настройки.** Профиль (только чтение), язык, организации и роли, доступные возможности. Смена имени и пароля не показана: в API таких маршрутов нет.

Горячие клавиши: `Ctrl/Cmd+K` палитра команд, `G` затем `O V Q D S M A B I L ,` переход по разделам, `?` список клавиш, `N` в списке заведений.

## Данные

TanStack Query, ключи начинаются с идентификатора организации. Оптимистично обновляются: настройки заведения и переключатель приёма заказов, коды (название, включение, удаление), роли и удаление людей, запрещённые слова. При ошибке значения откатываются и показывается тост. При смене периода на аналитике график остаётся на экране с приглушением, без скелетона.

Ошибки API переводятся в понятные сообщения (`src/lib/api-errors.ts`, `src/lib/error-messages.ts`): неверные данные, занятый адрес, последний владелец, лимиты с секундами до повтора, нет сети.

## Графики

Все графики на чистом SVG без библиотек, по навыку `dataviz`. Палитра для тёмной поверхности проверена валидатором: `#7d6bf0`, `#c98500`, `#199e70` (в таком порядке) проходят полосу яркости, порог насыщенности, различимость при дальтонизме и порог для обычного зрения. Серия 1 фиолетовая, серия 2 янтарная. Столбцы не толще 24 px и скруглены сверху на 4 px, линии 2 px, точки 8 px с кольцом цвета поверхности, сетка тонкая и сплошная. Подписан только пик и конец линии, остальное в подсказке. Подсказки работают и с клавиатуры (стрелки, фокус). Для двух и более серий показывается легенда. Шкала доли отклонённых меняет заливку по серьёзности (иконка и подпись дублируют цвет). Данные дублируются таблицей.

Ограничения данных API: `byDay` не длиннее 30 дней, сканирования QR накопительные и не зависят от периода (на странице есть пояснение), поэтому дельты для них не показываются.

## Тесты

```sh
pnpm --filter @joymusic/admin typecheck
pnpm --filter @joymusic/admin lint
pnpm --filter @joymusic/admin test
```

Vitest покрывает сессию (single-flight, ротация, повтор после 401, сброс при отказе, заголовок организации), разбор ошибок API, матрицу прав, преобразования данных графиков, slug, черновик настроек заведения, макеты QR, журнал аудита, форматы (в том числе узбекские даты и числа без зависимости от ICU браузера), каталог сообщений (одинаковые плейсхолдеры в трёх языках) и формы (вход, регистрация, приглашение, мастер заведения, модерация, диджеи, диалоги, десктоп, графики).

### E2E

```sh
pnpm --filter @joymusic/admin e2e
```

Playwright сам поднимает всё нужное: `e2e/start-api.mjs` запускает `apps/api/scripts/test-services.mjs start`, пересоздаёт базу `joymusic_admin_e2e`, применяет миграции, вызывает `db:seed`, добавляет активность скриптом `scripts/seed-activity.mjs` и запускает API на порту 4321. Панель собирается `vite build` и отдаётся `vite preview` на порту 5184. Chromium берётся из `PLAYWRIGHT_BROWSERS_PATH` (`/opt/pw-browsers`), `playwright install` не нужен.

Сценарии: вход, ошибка пароля, возврат на запрошенную страницу, обновление сессии после перезагрузки, регистрация, роли и страница для диджея, подтверждение десктопа, мастер заведения и настройки, конфликт адреса, удаление, QR (создание, предпросмотр, скачивание SVG, PNG и PDF, общий PDF на все столы, переименование, отключение, удаление), приглашение диджея и принятие ссылки, смена роли, защита последнего владельца, запрещённые слова, бан устройства, аналитика и обзор, палитра команд, горячие клавиши, переключение языка, биллинг, журнал аудита, планшетная ширина, брендинг.

## Скриншоты

`pnpm --filter @joymusic/admin screenshots` снимает каждый раздел в 1440×900 (и планшет 1024×768 для каркаса), состояния (загрузка, ошибка сети, пустая организация, диалоги, несохранённые изменения) и примеры на uz, ru, en в `docs/design/admin/`. Скрипт ожидает работающие API (`--api=`, по умолчанию `http://localhost:4320`) и панель (`--base=`, по умолчанию `http://localhost:5173`) с данными из `scripts/seed-activity.mjs`:

```sh
DATABASE_URL=postgres://joymusic:joymusic@127.0.0.1:54329/joymusic_dev node apps/admin/scripts/seed-activity.mjs
```

Скрипт добавляет три заведения (Lounge, Café, Club), около 90 сессий за 30 дней с четырьмя тысячами заказов, журнал аудита и одно приглашение. Он идемпотентен по сессиям и журналу.

## Известные ограничения

- В API нет маршрутов смены имени, пароля и разбана устройства, поэтому в панели их нет.
- Для проверки адреса заведения нет отдельного маршрута. Используется публичный `GET /v1/venues/:slug`: адрес другого заведения и своего выглядят одинаково занятыми.
- Токен приглашения сервер отдаёт только при создании. Потерянную ссылку заменяет новое приглашение.
- В `@joymusic/ui` у `EmptyState` иллюстрация получает классы `w-full` и `w-56` одновременно, и результат зависит от порядка утилит Tailwind. В панели размер задаёт обёртка `components/empty.tsx` и правила в `styles.css`.
- Файл логотипа и обложки загрузить нельзя, только ссылка: в API нет загрузки файлов.
- Мобильная вёрстка не целевая: панель рассчитана на планшет и выше (ниже 1180 px сайдбар сжимается до иконок).
