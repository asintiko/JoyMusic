# Интеграции: определение играющего трека, MIDI, каталог музыки

Документ описывает пакет `@joymusic/dj-bridge` и каталог `@joymusic/catalog`.

## Главное про честность

Ничего из перечисленного ниже не проверено на настоящем оборудовании и настоящем DJ-софте. Код писался в контейнере без CDJ, контроллеров, Serato, Traktor, VirtualDJ и Rekordbox. Поэтому в таблице три уровня:

- **Реализовано**: код написан, типизирован, работает в приложении.
- **Проверено на фикстурах**: есть автотесты на синтетических данных (файлы, сокеты, поддельные модули). Тесты доказывают, что код делает то, что мы задумали, но не доказывают, что формат совпадает с реальным.
- **Нужна проверка на железе**: подтвердить может только человек с настоящим оборудованием.

Форматы файлов Serato и VirtualDJ взяты из открытых реверс-проектов и вторичных описаний. Это не официальная документация: разработчики Serato, VirtualDJ и Traktor форматы не гарантируют, и они могут поменяться с обновлением программы.

## Как это устроено

Каждый источник это адаптер `NowPlayingAdapter`. Адаптер сообщает менеджеру `AdapterManager` состояние дек или один текущий трек. Менеджер:

1. выбирает деку «в эфире»: сначала дека с `onAir` (канал микшера открыт), иначе играющая, иначе загруженная последней;
2. ждёт стабильности (по умолчанию 1,5 с), чтобы не мигать при быстрых переключениях A → B → A;
3. не считает изменением тот же трек, записанный иначе (регистр, пробелы), но передаёт дополнение метаданных (например, пришёл BPM);
4. сообщает пустой трек только через паузу (по умолчанию 4 с), чтобы короткий разрыв при кроссфейдере не гасил экран гостей;
5. при нескольких включённых адаптерах побеждает тот, чей трек изменился последним.

События менеджера: `nowPlaying` и `status`. Результат можно превратить в `NowPlaying` из `@joymusic/shared` функцией `toNowPlaying`. Поля `requestId` и `dedicatedTo` сюда не заполняются: их сопоставляет уровень выше.

Для разработки есть `SimulatorAdapter` со сценарием треков.

### Pro DJ Link (Pioneer)

Пакет `prolink-connect` подключается динамическим импортом. Без него адаптер показывает статус «недоступно». Пакет тянет нативные зависимости (`better-sqlite3`), поэтому в десктоп его надо ставить и собирать отдельно и проверить в Electron.

Что берём: `onAir` из статуса плеера, BPM из статуса (иначе из метаданных), название, исполнителя, альбом, тональность и длительность из метаданных трека. Метаданные запрашиваются один раз на загрузку трека, ответ ограничен по времени. Нужен микшер DJM в сети, иначе плееры не сообщают `onAir`.

Открытые вопросы: единицы поля `tempo` в метаданных, поведение с несколькими устройствами, выбор сетевого интерфейса на компьютере с несколькими сетями. Ничего из этого не проверено.

### StageLinQ (Denon / Engine)

Существует поддерживаемая реализация: npm-пакет `stagelinq` (репозиторий chrisle/StageLinQ, версия 3.5.7 на момент написания). Мы не подключаем её как жёсткую зависимость: она тянет нативную библиотеку SQLite. Адаптер загружает пакет динамически, а при отсутствии пишет «недоступно».

По умолчанию `onAir` не выводится из громкости канала (`externalMixerVolume`): смысл поля не подтверждён, а ошибка погасила бы все деки. Включается опцией `useMixerVolume`. Без неё выбор идёт по «играет / загружена последней».

### VirtualDJ

Адаптер каждую секунду смотрит на самый новый `.m3u`, `.m3u8` или `.txt` в папке History и берёт последнюю запись. Проверяются несколько путей по очереди, побеждает первый существующий:

- macOS: `~/Library/Application Support/VirtualDJ/History`, затем `~/Documents/VirtualDJ/History`;
- Windows: `%LOCALAPPDATA%\VirtualDJ\History`, затем `Документы\VirtualDJ\History`.

Расположение папки зависит от версии и настроек VirtualDJ. Если ничего не найдено, укажите папку вручную.

Ограничение: история пишется после того, как трек сыграл. Это не «прямо сейчас» и не знает, какая дека в эфире. Для более точного варианта настройте в VirtualDJ запись текущего трека в текстовый файл и укажите его в опции `nowPlayingFile` (шаблон по умолчанию `{artist} - {title}`).

### Serato DJ Pro

Формат сессии: последовательность блоков «4 символа имени + 4 байта длины (big-endian)». Блок `vrsn` хранит версию, каждый `oent` содержит `adat`, а внутри лежат записи «номер поля (4 байта) + длина (4 байта) + данные». Строки в UTF-16BE, числа big-endian.

Номера полей, по открытому проекту SslScrobbler (Ben XO), и наше использование:

| Номер | Поле                     | Используем  |
| ----- | ------------------------ | ----------- |
| 6     | title                    | да          |
| 7     | artist                   | да          |
| 8     | album                    | да          |
| 10    | length (строка `мм:сс`)  | да          |
| 15    | bpm                      | да          |
| 28    | starttime (секунды Unix) | да          |
| 29    | endtime                  | да          |
| 31    | deck                     | да          |
| 45    | playtime                 | нет, читаем |
| 50    | played                   | да          |
| 51    | key                      | да          |
| 70    | ejected                  | да          |

Логика: для каждой деки берётся последняя запись. Если у неё есть `endtime` или `ejected`, дека считается пустой. `played = 0` означает «загружена, но не играет», такая дека проигрывает играющей. Оборванный хвост файла (запись в процессе) тихо пропускается.

Пути:

- macOS: `~/Music/_Serato_/History/Sessions`;
- Windows: `%USERPROFILE%\Music\_Serato_\History\Sessions`.

Если библиотека лежит на внешнем диске, у него свой каталог `_Serato_` в корне диска. Адаптер такие диски сам не ищет: путь нужно задать вручную.

Не проверено на реальных сессиях: когда именно Serato создаёт запись (при загрузке или при старте воспроизведения), когда записывается `endtime`, единицы BPM, как часто сбрасывается файл на диск. Тесты используют фикстуры, которые собирает наш же писатель формата: они подтверждают внутреннюю согласованность, но не сверяют с настоящим Serato.

### Traktor (Icecast)

У Traktor нет API, но он умеет вещать в Icecast-сервер. Мы поднимаем на `127.0.0.1` минимальный приёмник: принимает `SOURCE` и `PUT`, звук отбрасывает, метаданные берёт из запроса `GET /admin/metadata?mode=updinfo&mount=...&song=Artist - Title`, а если источник объявил `icy-metaint`, то и из потока. Порт по умолчанию 8000. Проверка пароля необязательна (логины `source` и `admin`). Нет поддержки протокола Shoutcast v1.

Настройка Traktor Pro:

1. Preferences → Broadcasting.
2. Address: `127.0.0.1`, Port: `8000`, Format: MP3, Mount Point: `/live` (любое), Password: тот, что задан в приложении (или пустой, если пароль не задан). Тип сервера Icecast 2.
3. Включите вещание кнопкой в верхней панели Traktor. Звук уйдёт в никуда, это нормально.
4. Статус в пульте: «ожидание» до подключения Traktor, «активен» после.

Что не проверено: реальный порядок запросов Traktor, кодировка названий (кириллица, узбекские апострофы), поведение при разрыве и переподключении. Ограничение метода: Traktor присылает только строку исполнитель-название, без BPM, тональности и без деки. Какая дека в эфире, приёмник не знает: Traktor сам решает, какой трек отправить.

### Mixxx

Отдельного адаптера нет. Лёгкого и безопасного способа читать историю Mixxx мы не нашли: она лежит в базе SQLite, которую пришлось бы открывать параллельно с работающим Mixxx. Зато Mixxx умеет вещание в Icecast (Preferences → Live Broadcasting), значит подойдёт тот же приёмник, что и для Traktor. Работоспособность не проверялась.

### Текстовый файл

Универсальный вариант для программ, которые пишут «сейчас играет» в файл. Шаблон поддерживает `{artist}`, `{title}`, `{album}`, `{bpm}`, `{key}`, обязателен `{title}`. Для однострочных шаблонов берётся последняя непустая строка файла, для многострочных весь текст. Пустой файл сбрасывает трек.

### Rekordbox

Официального API у Rekordbox нет, а база истории зашифрована. Мы не обходим шифрование и не читаем базу. Поддерживаемые пути:

1. Pro DJ Link: если играете на CDJ / XDJ, подключённых к сети, адаптер Pro DJ Link видит и треки из Rekordbox.
2. Текстовый файл: способ зависит от версии Rekordbox и его плагинов, мы его не гарантируем.
3. Ручная отметка «играет» в пульте.

Rekordbox в режиме Performance без внешнего железа этими способами не читается.

## MIDI

Работает в renderer через Web MIDI. Объект `MIDIAccess` передаётся снаружи, пакет его не запрашивает.

Возможности: список устройств и горячее подключение, привязки «сообщение → действие», режим обучения, сохранение в JSON, подсветка пэдов по состоянию очереди.

Действия: `acceptTop`, `declineTop`, `playNext`, `markPlayed`, `toggleRequestsOpen`, `moveSelection(+1 / -1)`, `pushToAir`.

Обучение: `learn(action)` возвращает обещание, которое выполняется на следующем сообщении `noteOn` (со скоростью больше нуля) или `cc` (значение больше нуля). Для `moveSelection` на `cc` привязка становится относительной: значения 1–63 это +1, 65–127 это −1. Если на `cc` висит обычная кнопка для `moveSelection`, передайте `relative: false`. Таймаут по умолчанию 15 с.

Подсветка: `acceptTop` мигает, пока есть необработанные заказы, `declineTop` горит при их наличии, `playNext` и `pushToAir` горят при непустой очереди, `markPlayed` горит, пока что-то играет, `toggleRequestsOpen` горит при открытом приёме. Сообщения уходят только на выходы, у которых то же имя, что и у подключённого входа: посторонние синтезаторы ничего не получат.

Пресеты: Pioneer DDJ-FLX4, DDJ-400, Numark Mixtrack, NI Kontrol S2, S4. **Все помечены `verified: false`.** Номера нот и каналов это стартовые догадки, которые никто не сверял с устройством. Надёжный путь это MIDI-обучение. Kontrol S2 и S4 поколений Mk2 и Mk3 по умолчанию работают по HID и, скорее всего, вообще не видны как MIDI-устройство.

## Устранение неполадок

| Симптом                                              | Что проверить                                                                                                                             |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Статус «недоступно» у Pro DJ Link или StageLinQ      | Пакет `prolink-connect` или `stagelinq` не установлен или не собран под Electron.                                                         |
| Pro DJ Link «ожидание»                               | Плееры и компьютер в одной сети и подсети, кабель или один Wi-Fi. Клиентская изоляция в гостевом Wi-Fi клуба блокирует обнаружение.       |
| Pro DJ Link не показывает «в эфире»                  | В сети нет микшера DJM. Выбор пойдёт по играющей деке.                                                                                    |
| Треков нет, статус «ожидание» у VirtualDJ или Serato | Папка не найдена: задайте путь вручную, убедитесь, что программа пишет историю (Serato пишет сессию только после начала воспроизведения). |
| Traktor: ошибка при запуске                          | Порт 8000 занят: смените порт и в приложении, и в Traktor.                                                                                |
| Traktor: статус «ожидание», хотя вещание включено    | Проверьте адрес, порт, тип сервера и пароль. Пароль должен совпасть, иначе Traktor получит 401.                                           |
| Названия с кракозябрами                              | Кодировка источника не UTF-8. Для файлов ожидается UTF-8.                                                                                 |
| Трек мигает на экране гостей                         | Увеличьте `debounceMs` менеджера.                                                                                                         |
| Трек пропадает на несколько секунд при кроссфейдере  | Увеличьте `clearAfterMs`.                                                                                                                 |
| MIDI: контроллер не виден                            | Драйвер, режим устройства (MIDI, а не HID), разрешение доступа к MIDI в Electron.                                                         |
| MIDI: пресет не срабатывает                          | Он не проверен на устройстве. Пройдите MIDI-обучение по действиям.                                                                        |

## Честные ограничения

- Ни один адаптер не проверен на реальном оборудовании или программе.
- Серато, VirtualDJ и Traktor могут изменить форматы без предупреждения.
- Файловые адаптеры опрашивают папку раз в секунду. Задержка обнаружения до пары секунд плюс задержка записи самой программой.
- VirtualDJ и Serato не сообщают «эфир» надёжно: используем «последний открытый трек на деке» и признак `played`.
- Traktor даёт только строку названия: без BPM, тональности и обложки.
- Pro DJ Link и StageLinQ требуют нативных пакетов, сборку в Electron на Mac и Windows нужно проверить.
- Обложек нет ни у одного адаптера. Обложку и `track` каталога подставляет уровень выше поиском по названию.
- Правовой статус чтения файлов чужого софта не оценивался.

## Каталог музыки (`@joymusic/catalog`)

**Условия использования Deezer и iTunes не проверены.** Перед продакшеном их надо перечитать: в частности, допустимость показа обложек и 30-секундных превью и лимиты запросов.

Провайдеры прячутся за интерфейсом `CatalogProvider`:

- **Deezer** (`https://api.deezer.com`) даёт поиск, чарты, плейлисты, обложки и 30-секундные превью. Ключ не нужен. Превью содержат срок жизни в ссылке (`hdnea=exp=...`), каталог сам определяет устаревшие ссылки и обновляет их через `refreshPreview`.
- **iTunes Search** (`https://itunes.apple.com`) запасной провайдер, тоже без ключа. Обложки увеличиваются заменой размера в ссылке.

Как работает поиск (`createCatalog`):

1. Запрос нормализуется (NFKC, пробелы, не длиннее 120 символов, минимум 2 символа).
2. **Транслитерация**: из запроса строятся варианты (`searchVariants`): кириллица в латиницу в трёх стилях (неформальный, русский, узбекский), латиница в кириллицу, варианты апострофов (`oʻ`, `gʻ`) и перестановки букв. Например, «Shahzoda» и «Шахзода» находят один и тот же трек. По умолчанию не больше 3 вариантов; стратегия `adaptive` пробует следующие варианты, только если сильных совпадений мало.
3. **Ранжирование**: покрытие слов запроса в названии и исполнителе (основной вес), бонусы за точное совпадение и за начало строки, популярность, наличие обложки и превью, небольшая надбавка за позицию у провайдера. Штраф за «мусор»: караоке, трибьюты, инструментальные версии, каверы, пока об этом не просили в запросе. Дубликаты из разных провайдеров склеиваются по фонетическому ключу.
4. **Кэш** (`CatalogCache`): память по умолчанию (до 500 записей) или Redis через `createRedisCache`. Время жизни: поиск и трек 8 минут, подборки до 6 часов, чарты до 30 минут. Ошибки кэша не ломают поиск.
5. **Устойчивость**: таймаут, повторы с паузой, лимит параллельных запросов и размыкатель цепи на каждого провайдера (по умолчанию 5 ошибок подряд, пауза 30 с). Если все провайдеры упали, бросается `CatalogUnavailableError`. Состояние провайдеров видно в `providerStatus()`.
6. **Подборки** (`suggestions`): разделы строятся из чартов, плейлистов и списка сидов (узбекские хиты, русский поп и другие), не более двух треков одного исполнителя в разделе.

Ограничения: узбекская музыка в Deezer и iTunes представлена слабо, поэтому для неё есть заказ по тексту. Живой смоук-тест каталога запускается вручную командой `pnpm --filter @joymusic/catalog test:live`, в обычные тесты сеть не входит.
