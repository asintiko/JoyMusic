# Десктоп диджея (`@joymusic/desktop`)

Пульт заказов и сцена для Mac и Windows: Electron 44, electron-vite, React 19, Tailwind 4. Диджей играет в привычном софте (Serato, Rekordbox, Traktor, VirtualDJ, CDJ). Своих дек и микшера в приложении нет. Приложение показывает заказы гостей и очередь, само определяет играющий трек, слушает MIDI-контроллер и выводит полноэкранную сцену на ТВ заведения.

Контракт с сервером живёт в `packages/shared` (маршруты, клиент, редьюсер состояния). Адаптеры оборудования и MIDI лежат в `packages/dj-bridge`, Joy Code для сцены в `packages/qr`, интерфейс в `packages/ui`. В этих пакетах десктоп ничего не менял.

## Запуск

```sh
node apps/api/scripts/test-services.mjs start
pnpm --filter @joymusic/api db:migrate && pnpm --filter @joymusic/api db:seed
pnpm --filter @joymusic/api dev
pnpm --filter @joymusic/admin dev
pnpm --filter @joymusic/desktop dev
```

Для входа через браузер нужна админка (страница `/desktop/authorize`). Без неё работает вход по email и паролю: `dj@joymusic.uz` / `joymusic-demo` из сида.

| Команда                                                       | Что делает                                                               |
| ------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `pnpm --filter @joymusic/desktop dev`                         | electron-vite dev с горячей перезагрузкой окна                           |
| `pnpm --filter @joymusic/desktop dev:shim`                    | тот же рендерер в обычном браузере на `http://127.0.0.1:5290` (см. ниже) |
| `pnpm --filter @joymusic/desktop build`                       | `electron-vite build` в `out/`                                           |
| `pnpm --filter @joymusic/desktop dist:dir`                    | сборка electron-builder без установщика (для проверки упаковки)          |
| `pnpm --filter @joymusic/desktop dist:mac` / `dist:win`       | dmg и zip для Mac, NSIS для Windows (только на своей ОС или в CI)        |
| `pnpm --filter @joymusic/desktop typecheck` / `lint` / `test` | проверки, обязательные в CI                                              |
| `pnpm --filter @joymusic/desktop test:e2e`                    | сквозные тесты против настоящего API                                     |
| `pnpm --filter @joymusic/desktop screenshots`                 | скриншоты в `docs/design/desktop/`                                       |

`dev:shim` подставляет вместо Electron IPC браузерный мост (`src/renderer/bridge/shim.ts`). Адрес API берётся из `?api=`, пространство хранилища из `?ns=`: `http://127.0.0.1:5290/?api=http://localhost:4000&ns=demo`. В shim работает только симулятор адаптеров, окна сцены нет (её страница открывается как `#/stage`). В боевую сборку shim не попадает: он подключается только в режиме `shim`.

## Архитектура

```
Renderer (React, песочница, без сети)      Main (Node)                              Внешний мир
------------------------------------      --------------------------------------   -----------------
Login, Venues, Console, Settings, Stage -> preload (contextBridge, типизированный) -> DesktopCore
                                              IPC только с zod-валидацией            auth-service   -> API (PKCE, refresh)
                                              topics: auth, net, outbox, adapters,   api-service    -> API (fetch из main)
                                              settings, session, stage, updates      commands+outbox-> диск (outbox.json)
                                                                                     realtime-hub   -> WebSocket API
                                                                                     adapter-host   -> Serato, VDJ, Traktor,
                                                                                     nowplaying-sync   Pro DJ Link, StageLinQ
```

Вся логика вне Electron собрана в `src/core` без импортов `electron` и `node:`. Её создаёт `createDesktopCore(env)`: в main с `safeStorage`, файлами в `userData` и `net.fetch`, в браузерном shim с `localStorage`. Поэтому сквозные тесты гоняют настоящие авторизацию, очередь офлайн-команд и realtime, а не копию.

### Почему сеть только в main

Рендерер не ходит в сеть: CSP держит `connect-src 'self'`. Так сделано по двум причинам. Сервер сверяет заголовок `Origin` у WebSocket и CORS у fetch, а рендерер с кастомной схемой `joy://app` прислал бы чужой origin. Для клиентов без `Origin` (main-процесс) эта проверка не применяется. Кроме того, токены не покидают main, а обновление токена, офлайн-очередь и переподключение живут в одном месте.

Рендерер получает состояние через `topics` (подписка плюс снимок при старте) и `realtime.subscribe`. Хаб держит по одному WebSocket на пару `venue:role`, применяет события через `applyServerEvent` и шлёт окнам готовое `VenueState`. Пульт подключается как `role=dj` с токеном, окно сцены как `role=tv` без токена.

### Вход

1. Кнопка «Продолжить в браузере»: main генерирует `codeVerifier` (64 символа), `state` и `codeChallenge = base64url(SHA256(verifier))`, открывает `${ADMIN_URL}/desktop/authorize?state=...&challenge=...` в системном браузере. Живёт 5 минут.
2. Админка вызывает `authDesktopAuthorize` и переводит браузер на `joymusic://auth?code=...&state=...`.
3. ОС отдаёт ссылку приложению: `open-url` на macOS, `second-instance` (аргументы командной строки) на Windows. Парсер (`src/core/deep-link.ts`) принимает только схему `joymusic`, хост `auth`, `code` и `state` в допустимом алфавите. `state` сравнивается за постоянное время. Чужой `state` не запускает обмен.
4. Main вызывает `authDesktopToken` с `codeVerifier`.

Запасной путь: форма email и пароля (`authLogin`). Access-токен обновляется за 30 секунд до конца срока. Обновление идёт в один запрос на всех (single-flight), новый refresh-токен записывается на диск раньше, чем возвращается результат. Ошибка сети не разлогинивает: сессия остаётся и работает из очереди. `401/403` на refresh стирает сессию.

Токены лежат в `userData/session.bin`, зашифрованы `safeStorage` (Keychain, DPAPI). Если система не умеет шифровать, включая слабый Linux-бэкенд `basic_text`, токены не пишутся на диск вообще: вход живёт до закрытия приложения.

### Офлайн-устойчивость

- Соединение оценивается по результатам запросов и по `GET /v1/health` (раз в 15 секунд, при обрыве 2, 4, 8, 10 секунд). Обрыв WebSocket запускает проверку сразу. Ответ, начатый до обрыва, не может вернуть статус «онлайн» (счётчик эпох).
- Действия диджея (принять, отклонить, играть, сыграно, порядок очереди, настройки сессии, автоопределённый трек) идут через `commands.run`. Онлайн команда выполняется сразу. Офлайн, на ошибке сети или на 5xx и 429 она попадает в очередь `userData/outbox.json` и переживает перезапуск.
- Очередь воспроизводится по порядку. Новые команды встают за уже накопленными. Сжатие: остаётся последний `reorder` сессии и последний `nowplaying.*`.
- Ответ сервера при повторе: сеть или 5xx останавливают проход, 400/403/404/409/422 значит, что заказ уже изменился, команда отбрасывается с пометкой в `outbox.lastSkipped`. `401` останавливает очередь до нового входа. Записи старше шести часов отбрасываются. Повтор идемпотентен за счёт статусной машины сервера: повторный `accept` даёт `409`, и это считается успехом-отбраковкой.
- Интерфейс сразу показывает эффект команды (`overlay.ts`): принятый заказ переезжает в очередь, отклонённый исчезает. Над списком появляется красная плашка «Нет связи» с числом сохранённых действий, кнопкой «Повторить сейчас» и чипом в строке состояния. Пока соединение восстанавливается, а сокет закрыт, плашка жёлтая.
- После восстановления связи: проигрывается очередь и запрашивается новый снимок (`resync`).

### Автоопределение трека

Адаптеры из `@joymusic/dj-bridge/node` запускает `adapter-host` в main. Менеджер адаптеров сглаживает дребезг (1,5 с на смену трека, 4 с на пропажу). Событие уходит в `nowplaying-sync`, который:

1. ждёт активную сессию (пульт сообщает её через `session.activate`);
2. если адаптер не дал обложку, ищет её по «исполнитель название» через `catalogSearch` (таймаут 2,5 с, кэш, ошибки не мешают);
3. нормализует BPM и ключ и отправляет `djNowPlayingSet` через ту же очередь. Метаданные того же трека обновляются на месте. Пауза между треками отправляет `djNowPlayingClear`;
4. связь с принятым заказом делает сервер по нормализованным исполнителю и названию.

Ручные действия: «Играет» на строке очереди и «В эфир» (Space) шлют `djRequestPlay`, «Отметить сыгранным» (P) шлёт `djRequestPlayed`, а без связанного заказа `djNowPlayingClear`.

### Адаптеры

| Адаптер           | Настройка                                          | Статус в проверках                                             |
| ----------------- | -------------------------------------------------- | -------------------------------------------------------------- |
| Serato DJ         | папка `_Serato_` (по умолчанию `~/Music/_Serato_`) | на фикстурах и в реальном Electron: «папка не найдена»         |
| VirtualDJ         | папка истории, необязательный файл текущего трека  | на фикстурах                                                   |
| Traktor (Icecast) | порт (8000) и пароль, инструкция в интерфейсе      | приёмник слушает порт в реальном Electron                      |
| Текстовый файл    | путь и шаблон `{artist} - {title}`                 | на фикстурах                                                   |
| Pro DJ Link       | переключатель                                      | модуль `prolink-connect` грузится, статус «ожидание сети»      |
| StageLinQ         | переключатель                                      | модуль `stagelinq` подключается из `asar` без падений          |
| Симулятор         | переключатель, кнопка «следующий трек»             | сквозной тест: трек попадает на сервер и связывается с заказом |

`prolink-connect` и `stagelinq` стоят в `optionalDependencies` и подключаются динамическим `import()`. Если пакета нет или он не загрузился, адаптер получает статус `unavailable`, приложение продолжает работать. У `prolink-connect` есть нативная зависимость `better-sqlite3@7`, которую pnpm не собирает и которая под Electron 44 скорее всего не соберётся. Поэтому в конфиге упаковки `npmRebuild: false`. Что метаданные с настоящих CDJ читаются, проверить нечем.

### MIDI

Web MIDI работает в рендерере (`navigator.requestMIDIAccess`), main выдаёт разрешение только на `midi` и только для своего origin. Режим обучения на каждое действие пульта (принять, отклонить, играть следующий, в эфир, сыграно, пауза приёма, выделение вверх и вниз), пресеты Pioneer DDJ-FLX4 и DDJ-400, Numark Mixtrack, Traktor Kontrol S2 и S4. Все пресеты помечены «Не проверено»: номера нот взяты как отправная точка, на устройствах не проверялись. Привязки хранятся в `userData/midi-bindings.json`. Подсветка пэдов (LED) показывает число новых заказов, очередь и воспроизведение и отключается в настройках.

### Окно сцены

Отдельное окно без рамки. Выбирается дисплей (по умолчанию первый внешний), включается киоск: Windows `setKiosk`, macOS `setSimpleFullScreen`. Окно поверх остальных, блокирует сон экрана (`powerSaveBlocker`), не закрывается случайно (Esc, F11, Ctrl или Cmd+W, F5, DevTools перехвачены), следит за отключением и сменой дисплея. Внутри те же визуалы, что у ТВ-экрана в `docs/DESIGN.md`: герой играющего трека, настоящий Joy Code с логотипом (`@joymusic/qr`, тема сцены, ссылка `${WEB_URL}/v/<slug>`), «Дальше», лента и посвящения. Режим простоя показывает призыв заказать трек. Управления нет, сцена только смотрит: состояние приходит тем же realtime (`role=tv`). Тема сцены следует теме заведения или задаётся вручную.

### Безопасность

- `contextIsolation`, `sandbox`, `nodeIntegration: false`, `webviewTag: false`, `webSecurity`, DevTools только в неупакованной сборке.
- Рендерер отдаётся своей схемой `joy://app` (не `file://`). CSP в ответе: `script-src 'self'`, `connect-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, без `unsafe-eval`. Для dev-сервера Vite CSP расширяется, но только когда он реально запущен.
- Навигация и `window.open` запрещены (`will-navigate`, `will-redirect`, обработчик открытия окон). Ссылки `http(s)` открываются во внешнем браузере, остальные схемы блокируются.
- Все IPC-сообщения проверяются zod-схемами, отправитель проверяется по origin. Запросы к API проверяются схемой самого маршрута до отправки. Доступен только белый список маршрутов диджея.
- Единственный экземпляр приложения (`requestSingleInstanceLock`).

## Автообновление и релиз

`electron-updater` с GitHub-провайдером. В разработке и при `JOYMUSIC_DISABLE_UPDATES=1` выключен. Проверка через 15 секунд после старта и раз в шесть часов, скачивание в фоне, установка при выходе. Переключатель и ручная проверка на вкладке «Обновления».

Релиз собирает `.github/workflows/desktop-release.yml`. Тег `desktop-v<версия>` запускает матрицу `macos-latest` и `windows-latest`: сборка, упаковка, затем задача `publish` создаёт релиз GitHub и прикладывает `dmg` (arm64 и x64), `zip` (нужен macOS для автообновления), `exe`, `blockmap` и `latest*.yml`. Версия берётся из тега. Ручной запуск (`workflow_dispatch`) собирает артефакты без релиза. Без секретов подписи сборки получаются неподписанными.

Важно для автообновления: провайдер GitHub берёт последний релиз репозитория. Пока в `asintiko/JoyMusic` выходят только десктопные релизы, всё работает. Если появятся релизы других продуктов, вынесите десктоп в отдельный репозиторий и задайте `JOYMUSIC_RELEASE_OWNER` и `JOYMUSIC_RELEASE_REPO`.

### Секреты репозитория

| Секрет                        | Для чего                                                            |
| ----------------------------- | ------------------------------------------------------------------- |
| `MAC_CSC_LINK`                | сертификат Developer ID Application в `.p12`, закодированный base64 |
| `MAC_CSC_KEY_PASSWORD`        | пароль от `.p12`                                                    |
| `APPLE_ID`                    | Apple ID для нотаризации                                            |
| `APPLE_APP_SPECIFIC_PASSWORD` | пароль приложения для этого Apple ID                                |
| `APPLE_TEAM_ID`               | идентификатор команды разработчика                                  |
| `WIN_CSC_LINK`                | сертификат подписи кода для Windows (`.pfx`, base64)                |
| `WIN_CSC_KEY_PASSWORD`        | пароль от `.pfx`                                                    |

Переменные репозитория (не секреты): `JOYMUSIC_API_URL`, `JOYMUSIC_ADMIN_URL`, `JOYMUSIC_WEB_URL`.

Если `MAC_CSC_LINK` пуст, отключается автопоиск идентичности (`CSC_IDENTITY_AUTO_DISCOVERY=false`) и Mac-сборка не подписывается. Нотаризация (`build/notarize.mjs`, хук `afterSign`) молча пропускается, если нет хотя бы одного из трёх `APPLE_*`. То же для Windows и `WIN_CSC_LINK`.

### Подпись

- **macOS.** Нужна учётная запись Apple Developer Program (99 долларов в год) и сертификат «Developer ID Application». Включён hardened runtime, права в `build/entitlements.mac.plist` и `build/entitlements.mac.inherit.plist` (JIT и неподписанная память для V8, отключённая проверка библиотек для опциональных модулей, сеть). Без подписи и нотаризации Gatekeeper покажет предупреждение, а автообновление на macOS требует подписанного приложения.
- **Windows.** Подойдёт сертификат подписи кода (OV или EV) в `.pfx`. Без него SmartScreen предупреждает при установке. EV убирает предупреждение сразу, у OV репутация накапливается. Альтернатива без файла сертификата: Azure Trusted Signing (нужна отдельная настройка `win.azureSignOptions`).
- Протокол `joymusic://` регистрируется установщиками (`protocols` в конфиге упаковки) и при запуске через `setAsDefaultProtocolClient`.

## Что не проверено

- **Реальное оборудование.** Serato, Rekordbox, VirtualDJ, Traktor, CDJ и StageLinQ проверены только на фикстурах и симуляторе. Метаданные Pro DJ Link из-за `better-sqlite3` под Electron 44 могут не читаться. Rekordbox отдельного адаптера не имеет: его можно подключить через текстовый файл.
- **MIDI-контроллеры.** Пресеты непроверенные, подсветка пэдов проверена только на подставном `MIDIAccess`.
- **Сборки Mac и Windows.** Собран и запущен только Linux `--dir`. `dmg`, `zip`, NSIS, подпись, нотаризация, регистрация `joymusic://` установщиком, `open-url` на macOS, `safeStorage` на Mac и Windows, `setSimpleFullScreen` на втором дисплее macOS и автообновление на настоящем релизе не пробовались.
- **Вход из настоящей админки.** В тестах страницу `/desktop/authorize` заменяет вызов `authDesktopAuthorize` из теста. Обмен кода и `state` через настоящую ссылку проверен в реальном Electron.
- **Тексты.** Узбекские и русские строки не вычитаны носителем.

## Известные ограничения

- Если WebSocket недоступен долго (прокси режет), запасного опроса `djSessionState` нет: пульт покажет «Реалтайм: офлайн» и последнее известное состояние.
- Сервер не принимает ключ идемпотентности. Защита от двойной отправки опирается на статусную машину заказов.
- Переставить заказ мышью можно только внутри очереди. Из входящих заказ попадает в очередь кнопкой «Принять». «Позже» действует только локально до перезапуска.
- Заголовки панелей (`type-eyebrow`) в бандлированных шрифтах иногда рисуются с лишним просветом после буквы (например «SET TINGS»). Причина в стиле дизайн-системы, в `packages/ui` не менялось.
- Значки приложения берутся из `packages/brand/assets/icons` без отдельной подготовки под Windows-плитки и Dock.
